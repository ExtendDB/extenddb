# Verifying ExtendDB container images

Images released after build attestations were added (the first such release is named in the release notes) carry GitHub artifact attestations, signed through Sigstore and stored with the ExtendDB repository:

- Build provenance (SLSA v1), generated by GitHub for the release workflow run that built the image. One provenance attestation covers the multi-architecture image index and both per-architecture images.
- A CycloneDX SBOM for each per-architecture image, listing the operating system packages and the Rust crates that Cargo resolved for the `extenddb` binary. That crate list can include crates the binary does not link.

So the index carries one attestation, the provenance, and each per-architecture image carries two. The release workflow `release-image.yml` makes them for `extenddb-postgres` and `extenddb-mongodb`, and `release-dev-image.yml` makes them for `extenddb-dev`. A release whose attestation job did not complete can lack them. Verifying them needs the GitHub CLI, signed in to any GitHub account.

## Build provenance

First resolve the release tag to its index digest; the `Digest:` line of the output is the one to use:

```console
docker buildx imagetools inspect docker.io/extenddb/extenddb-postgres:X.Y.Z
```

Then verify that digest:

```console
gh attestation verify oci://docker.io/extenddb/extenddb-postgres@sha256:<index digest> \
  --repo ExtendDB/extenddb \
  --cert-identity https://github.com/ExtendDB/extenddb/.github/workflows/release-image.yml@refs/heads/main
```

The certificate identity pins the release workflow as it runs from `main`. For `extenddb-dev`, use `release-dev-image.yml` in the identity. The same command works against `ghcr.io/extenddb` and `public.ecr.aws/extenddb`, which serve the same digests.

The provenance records the workflow, the commit of `main` it ran from, and the run. The commit the image was built from is the image's `org.opencontainers.image.revision` label, which the verified digest covers. Read it from the same digest:

```console
docker pull docker.io/extenddb/extenddb-postgres@sha256:<index digest>
docker inspect --format '{{ index .Config.Labels "org.opencontainers.image.revision" }}' \
  docker.io/extenddb/extenddb-postgres@sha256:<index digest>
```

## SBOM

Each SBOM is attested to its per-architecture image. The `imagetools inspect` output above lists the per-architecture digests. Verify the SBOM for one architecture and save it:

```console
gh attestation verify oci://docker.io/extenddb/extenddb-postgres@sha256:<linux/amd64 digest> \
  --repo ExtendDB/extenddb \
  --cert-identity https://github.com/ExtendDB/extenddb/.github/workflows/release-image.yml@refs/heads/main \
  --predicate-type https://cyclonedx.org/bom \
  --format json --jq '.[0].verificationResult.statement.predicate' > sbom-amd64.cdx.json
```
